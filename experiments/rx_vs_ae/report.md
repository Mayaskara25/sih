# Phase 5 Level 1 — classical detector benchmark

Generated by `scripts/run_benchmark.py`. Regenerate with
`.venv/bin/python scripts/run_benchmark.py --datasets abu,hydice`.

**Every number here is scene-macro-average unless the column says `micro`.**
ABU's anomaly density spans 0.084 %–2.72 %, a 32× range (D13.2), so a
pixel-weighted pool is effectively a report on `abu-urban-4` and `abu-beach-2`
and says almost nothing about `abu-beach-1`. §3A.10 makes macro primary and
bans an unlabelled "pooled" figure; both columns appear together everywhere
below, and the macro column is the headline.

Detectors were called on **standardized** input. That is a recorded choice,
not a default: D22 found `global_rx` raising `LinAlgError` on 3 of 13 ABU
scenes when called on native radiance, and two detectors compared under
different input scalings are not comparable.

## What these numbers say, and what they do not

**`crd` leads on ABU** (0.9674 macro) and `kernel_rx` follows (0.9624). Both
beat `global_rx` (0.9447). That ordering is the defensible headline.

**`local_rx` (0.9389) does not beat `global_rx` here, and §3A.2's accept
criterion said it should.** It does beat it comfortably on individual scenes —
0.9647 vs 0.8202 on `abu-airport-1` — so this is a per-scene-vs-macro effect,
not a broken detector. Two things are worth stating rather than smoothing
over: the window is now chosen per scene size (§3A.2 forbids carrying HAD100's
64×64 params to ABU's 100×100/150×150 scenes, and doing so cost 0.012 macro
and last place in the first run of this harness), and even so the macro
average is dragged down by the scenes where a fixed annulus size suits the
target scale badly. **The §3A.2 criterion holds per scene and does not hold on
the macro average.** Both facts belong in any table that cites it.

**`fused` is last on ABU (0.9350).** This is consistent with D25, which ran
§3A.9's prescribed weight grid search on a held-out split and found fusion
beating the best fixed single component by +0.0018 macro AUC — noise — while
the optimizer assigned ACE a weight of exactly 0.0. **The report must not
claim fusion beats its components.** What fusion legitimately offers is
comparable performance without a per-scene detector choice, since the
per-scene oracle is unavailable at inference time.

**Macro exceeds micro for every detector on ABU.** That is the D13.2 density
effect made visible: performance is systematically worse on the
anomaly-dense scenes that dominate a pixel-weighted pool. Anyone quoting a
single "pooled AUC" would be quoting the lower number without knowing it.

**PR-AUC is far below ROC-AUC everywhere** (0.32–0.43 vs 0.94–0.97). With
anomaly fractions under 3 %, ROC-AUC is the flattering metric and PR-AUC is
the informative one. Both are reported for that reason.

## Not covered here

- **HAD100** is not in this run. It is the only benchmark shipping real
  wavelengths (D13.4/O8), so it is the only place the **4-component** fusion
  the plan specifies can run at all, and the only legal scoring set for
  learned models. Run `--datasets had100` to add it.
- **`streaming_rx`** is excluded: it takes a scene path, not a cube
  (`PATH_DETECTORS`), and its value is peak RSS rather than AUC. Its own
  module documents that `.mat` cannot stream, which is most of this set.
- **Stage-1 recall and the false-negative audit** are in
  `experiments/cascade_recall_audit/`, per §8 Level 1 — every missed labelled
  component with its extent, mean and max score, and the margin by which it
  missed the threshold. §13 rule 9 requires stage-1 recall to be reported
  separately from end-to-end accuracy.
